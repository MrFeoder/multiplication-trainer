# Тренажёр таблицы умножения — дизайн

Дата: 2026-10-17
Статус: одобрен в чате, ожидает проверки spec

## 1. Цель

Отдельный статический сайт-тренажёр для заучивания **таблицы умножения**. Пользователь
сам задаёт, что тренировать (диапазоны обоих множителей), какие виды заданий включить и
как отвечать (вписать или выбрать из вариантов).

Основной пользователь — школьник. Дополнительно есть профили «Взрослый» и «Нейтральный»,
которые меняют оформление и значения по умолчанию.

Сайт новый и независимый от существующих проектов: репозиторий
`MrFeoder/multiplication-trainer`, папка `C:\Users\Фёдор\multiplication-trainer`.
Проекты `MrFeoder/math-trainer` и `C:\Users\Фёдор\site` (`MrFeoder/besplatniy-sait`)
не изменяются.

## 2. Границы (scope)

Входит:
- Один тренажёр таблицы умножения.
- Два диапазона: первый множитель (A) «от… до…», второй множитель (B) «от… до…».
- Четыре вида заданий, включаются галочками (можно несколько):
  1. прямой — `7 × 8 = ?`;
  2. пропущенный множитель — `7 × ? = 56` и `? × 8 = 56`;
  3. обратный — `56 = ? × ?`;
  4. деление — `56 ÷ 7 = ?` и `56 ÷ 8 = ?`.
- Тип ответа: вписать число / выбрать из 4 вариантов.
- Раунд из N вопросов, экран итогов, разбор ошибок, лучший результат.
- Профили оформления с сохранением настроек.
- Публикация на GitHub Pages.

Не входит (YAGNI):
- Аккаунты, серверная часть, база данных.
- Общий рейтинг между пользователями.
- Сложение, вычитание, дроби, степени (это тренажёр из другого проекта).
- Напоминания, звуки, картинки, таймер на вопрос.

## 3. Технологии

Как в предыдущем тренажёре:
- Чистые HTML + CSS + JavaScript, без сборки и внешних зависимостей.
- Скрипты подключаются обычными тегами (не ES-модули), чтобы страница работала и по
  `file://`, и на GitHub Pages.
- `logic.js` — UMD: в браузере создаёт глобальный объект `MTM`, в Node отдаётся через
  `module.exports`. Это даёт тестируемые чистые функции без DOM.
- Тесты — встроенный раннер Node (`node --test`), без внешних пакетов.
- Хранение настроек и лучших результатов — `localStorage`.
- Целевые браузеры: современные Chrome/Firefox/Edge/Safari, включая мобильные.

## 5. Экраны и интерфейс

Один экран, три состояния, переключаемые без перезагрузки.

### 5.1 Настройки
- **Профиль**: «Школьник» (по умолчанию) / «Взрослый» / «Нейтральный». Задаёт тему и
  стартовые значения; после ручных правок настройки больше профилем не перезаписываются.
- **Диапазон A** (первый множитель): поля «от» и «до».
- **Диапазон B** (второй множитель): поля «от» и «до».
  - По умолчанию: школьник 2–9 × 2–9, взрослый 2–12 × 2–12, нейтральный 2–10 × 2–10.
  - Допустимо: целые 1–100, «от» ≤ «до».
- **Какие задания**: четыре галочки (`direct`, `missing`, `reverse`, `division`).
  По умолчанию отмечены все четыре. Нужна хотя бы одна.
- **Тип ответа**: «Вписать» / «Выбрать из вариантов». По умолчанию — «Вписать».
- **Вопросов в раунде**: целое 1–100, по умолчанию 10.
- Кнопка **«Начать»** (заблокирована, пока есть ошибки настроек).

Настройки сохраняются в `localStorage` и восстанавливаются при следующем открытии.

### 5.2 Тренировка
- Прогресс «Вопрос 3 из 10», счётчики верных/ошибок, таймер (мм:сс).
- Крупная карточка с текстом задания.
- Режим «Вписать»: одно поле ввода (только цифры) + кнопка «Ответить», Enter подтверждает.
  Для обратного задания — **два** поля с разделителем `×`.
- Режим «Выбрать»: 4 кнопки. Для числовых заданий — 4 числа, для обратного — 4 пары
  (`7 × 8`, `6 × 9`, …).
- После ответа карточка и выбранная кнопка подсвечиваются зелёным/красным, при ошибке
  показывается правильный ответ; ответы блокируются на ~0.9 с, затем следующий вопрос.
- Кнопка «Прервать» возвращает в настройки (результат не сохраняется).

### 5.3 Итоги
- «Верно X из N» и процент.
- Время.
- Разбор ошибок списком: `7 × 8 = ?` → «вы: 54, верно: 56»; для обратного —
  `56 = ? × ?` → «вы: 6 × 8, верно: 7 × 8».
- Лучший результат для текущего типа ответа, набора заданий и диапазонов.
- Кнопки «Ещё раз» (новый раунд с теми же настройками) и «Изменить настройки».

## 6. Модель данных

```js
// Настройки
{
  profile: "kid" | "adult" | "neutral",
  aFrom: 2, aTo: 9,               // целые 1..100, aFrom <= aTo
  bFrom: 2, bTo: 9,               // целые 1..100, bFrom <= bTo
  formats: ["direct","missing","reverse","division"],  // непустое подмножество
  answerType: "input" | "choice",
  roundLength: 10                 // целое 1..100
}

// Вопрос
{
  format: "direct" | "missing" | "reverse" | "division",
  a: 7, b: 8, product: 56,
  variant: "" | "askB" | "askA" | "divA" | "divB",
  pair: false,                     // true только для обратного
  prompt: "7 × 8 = ?",
  answer: 56,                      // число (для обратного — произведение)
  answerText: "56"                 // как показывать ответ; для обратного — "7 × 8"
}

// Итог раунда
{ total, correct, seconds, mistakes: [{ prompt, given, answer }] }
```

Ключи `localStorage` (префикс `mtm.`, чтобы не пересекаться с прошлым сайтом `mt.`):
- `mtm.settings` — настройки.
- `mtm.profile` — выбранный профиль (для темы).
- `mtm.best.<answerType>.<formats>.<aFrom>-<aTo>.<bFrom>-<bTo>` — лучший результат,
  где `<formats>` — выбранные виды заданий, отсортированные и соединённые `+`
  (например `direct+division+missing+reverse`).

## 7. Логика (чистые функции)

1. `toInt(value)` — строка из одних цифр в целое, иначе `NaN` (пробелы обрезаются).
2. `defaultsFor(profile) -> Settings`.
3. `applyProfile(settings, profile) -> Settings` — подставляет диапазоны профиля, прочие
   поля сохраняет.
4. `validateSettings(settings) -> { ok, errors, warnings }`.
   Проверяет: диапазоны A и B — целые `1..100` и `от ≤ до`; `formats` — непустой массив
   из допустимых значений; `answerType` и `roundLength` корректны.
   Предупреждение (не блокирует), если `aTo > 20` или `bTo > 20`.
5. `normalizeSettings(raw) -> Settings` — мусор заменяется умолчаниями (для чтения из
   `localStorage` и из полей формы).
6. `buildPool(settings) -> Question[]`.
   По одному прямому и обратному вопросу на каждую пару (a, b); по два вопроса
   «пропущенный множитель» и два «деление» (оба варианта позиции). Только для выбранных
   видов заданий. При `aFrom > aTo` или `bFrom > bTo` возвращает `[]`.
7. `questionKey(question) -> string` — `format:a x b:variant`, уникален в пуле.
8. `shuffle(array)` — Fisher–Yates, новый массив.
9. `nextQuestion(pool, usedKeys, lastKey)` — случайный неиспользованный вопрос; при
   исчерпании пула начинает заново, не повторяя предыдущий.
10. `makeChoices(question, count = 4)`:
    - числовые задания → массив уникальных положительных чисел, ровно одно верное;
    - обратное → массив пар `{ a, b }`, ровно одна с нужным произведением.
    Дистракторы числовых заданий: типичные ошибки таблицы
    (`произведение ± a`, `± b`, `± 1`, `(a±1)·b`, `a·(b±1)`); для «пропущенного
    множителя» и «деления» — соседние числа и второй множитель. Дистракторы обратного —
    соседние пары с другим произведением.
11. `checkAnswer(question, given)`:
    - числовые задания — числовое сравнение (`07` == `7`, `49.0` — не число → `false`);
    - обратное — `given` это `{ a, b }`: верно, если оба целые ≥ 1 и их произведение
      равно `product` (**любая** верная пара, включая перевёрнутую).
12. `formatTime(seconds) -> "мм:сс"`.
13. `summarize(round) -> Result` — проценты, время, разбор ошибок.
14. `bestKey(settings) -> string`.
15. `isBetter(a, b)` — больше верных лучше; при равенстве — меньше времени.

Формулировки:
- прямой: `a × b = ?`;
- пропущенный множитель: `a × ? = произведение` или `? × b = произведение`;
- деление: `произведение ÷ a = ?` или `произведение ÷ b = ?`;
- обратный: `произведение = ? × ?`.

## 8. Обработка ошибок и краевые случаи

- Диапазоны: пусто, дробь, 0, отрицательное, «от» > «до», > 100 — текст ошибки на
  русском, «Начать» заблокирована.
- Ни одной отмеченной галочки — ошибка «выберите хотя бы один вид задания».
- Большие множители (`> 20`) — предупреждение, не блокирует.
- `aFrom == aTo` и/или `bFrom == bTo` (в т.ч. `7..7 × 1..10`) — работает, вопросы
  повторяются корректно.
- `roundLength` больше пула — пул переиспользуется без повторов подряд.
- В поля ввода пускаются только цифры; пустой ответ — мягкое «Введите ответ», без
  засчитанной ошибки. Для обратного задания пусто хотя бы в одном из двух полей — то же
  сообщение.
- Двойной быстрый клик по варианту не засчитывается дважды.
- Битый или недоступный `localStorage` — значения по умолчанию, консоль чистая.
- Сравнение чисел числовое, поэтому `07` и `7` равнозначны.

## 9. Тестирование

Автотесты `node --test`:
- `validateSettings`: корректные и все ошибочные варианты (включая пустой `formats`).
- `defaultsFor` / `applyProfile` / `normalizeSettings`.
- `buildPool`: размер и состав для каждого вида задания и комбинаций; обратный диапазон → `[]`.
- `nextQuestion`: нет повторов подряд, пул переиспользуется.
- `makeChoices`: 4 уникальных варианта, ровно один верный — для чисел и для пар.
- `checkAnswer`: число (`07` == `7`), пара (любая верная, включая перевёрнутую), мусор.
- `summarize`, `formatTime`, `bestKey`, `isBetter`.
- `markup.test.js`: все нужные id присутствуют, порядок скриптов, темы, нет внешних ресурсов.
- `ui.test.js`: стартовое состояние, ошибки/предупреждения, оба типа ответа (включая
  обратный с двумя полями и с парами), раунд до итогов и лучший результат, смена
  профиля, битый и недоступный `localStorage`, Enter, отбрасывание нецифр, «Прервать».

Ручной чек-лист (прогнать перед публикацией):
- Все виды заданий × оба типа ответа — раунд доходит до итогов.
- Граничные диапазоны: `1..1`, `7..7 × 1..10`, `12..12 × 12..12`.
- Кривой ввод: пусто, `0`, `-5`, `1.5`, `ab`, «от» > «до», `999`, ни одной галочки.
- Обратное задание: верна перевёрнутая пара, неверная пара не засчитывается.
- Enter подтверждает ответ; повторный клик не дублирует засчёт.
- Перезагрузка — настройки восстановились.
- Ширина 360 px и 1440 px — верстка не ломается.
- Консоль без ошибок; работает по `file://` и на GitHub Pages.
